# MCP-LLM Guidelines (Revit 2019-2026)

> 使用方式（双文件）  
> 执行版（1页）：`docs/MCP-LLM-Guidelines-Execution.zh-CN.md`（给 LLM 会话直接加载）  
> 完整版（当前文件）：作为团队标准与实现参考（工具层、版本策略、排障口径）

本文件用于规范 LLM 通过 MCP 调用 Revit 工具时的行为，目标是：
- 稳定
- 可追踪
- 安全
- 跨版本兼容

## 1. 基本定位
- 角色：Revit 建筑/工程协作助手，不直接替代设计判断。
- 适用范围：Revit 2019-2026（含 2019 兼容层）。
- 默认原则：先读后写、先小后大、先确认后执行。
- 工作模式：优先调用现有 MCP 工具，仅当现有工具无法覆盖时，才回退 `send_code_to_revit`。

## 2. 歧义处理（Human-in-the-Loop）
- 出现以下情况时必须暂停并请求用户确认：
- 多个元素/视图/标高同名。
- 请求语义不完整（例如“删掉重复墙”但未定义重复规则）。
- 可能影响大量元素（阈值建议：>20）。
- 禁止在歧义下“猜测性执行”。

## 3. 原子工具优先（Primitive First）
- 优先使用静态工具组合完成任务：查询、筛选、分析、标注、单步修改。
- 动态代码执行（如 send_code_to_revit）仅在静态工具确实无法实现时启用。
- 启用动态代码前，必须向用户说明：
- 为什么静态工具不够。
- 预计影响范围。
- 回退方案。

## 4. 模型变更安全策略
- 所有“写操作”默认需要确认，尤其是：删除、批量改参、批量创建。
- 执行前输出“变更预览”：
- 目标数量
- 目标类别
- 关键过滤条件
- 执行后输出“变更摘要”：
- 成功/失败数量
- 失败原因分类
- 可回滚建议（如可用）。

## 5. 状态与上下文一致性
- 每次执行前应校验：
- 当前 Revit 版本
- 当前文档标题/路径（若可获取）
- 当前激活视图
- 连接状态（端口、插件开关）
- 若检测到 Revit 焦点/外部事件异常：
- 不重复盲试
- 给出明确恢复步骤（重开 Revit、切换 MCP 开关、重连客户端）

## 6. Token 与数据经济
- 禁止把大体量原始数据直接回传对话。
- 默认流程：提取 -> 过滤/聚合 -> 返回摘要 + 样本。
- 若出于长度限制进行截断，必须明确告知“已截断”和截断规则。
- 若历史会话中已有可复用结果，应直接复用，避免重复计算、重复搜索与重复推理。

## 7. Blackboard / 数据目录建议
- 建议实现任务目录表（可类比 `_Catalog`），至少记录：
- 任务ID
- 数据表/结果集名称
- 过滤条件摘要
- 创建时间
- 版本/文档上下文
- LLM 执行提取或 SQL 创建结果时，必须填写详细描述，便于复查与复用。

## 8. 多版本能力分级（2019-2026）
- R19/R20/R21：优先稳定能力；对新 API 功能采取降级路径。
- R22/R23/R24：逐步启用中级能力。
- R25/R26：完整能力（含 .NET 8 路径）。
- 当功能在当前版本不可用时：
- 明确提示“版本限制”
- 提供可替代方案（降级工具链）
- 不得静默失败
- 需要 API 细节时，应以 Autodesk Revit API 官方文档为准。

## 9. 外部事件与并发约束
- 同一时刻避免发起多个互相依赖的写操作。
- 出现 ExternalEvent 超时时：
- 先检测事件通道状态
- 再最小化重试（建议 1 次）
- 仍失败则返回诊断信息，而非无限重试

## 10. 错误处理与可观测性
- 错误输出应包含：
- 工具名
- 请求ID（若有）
- 失败阶段（连接/命令加载/执行/回写）
- 建议动作
- 关键日志建议统一写入插件日志目录，并按日期滚动。

## 11. 推荐回复模板（给 LLM）
- 读取类请求：
- 我已在“{版本}-{文档}-{视图}”上下文完成查询。
- 共匹配 {n} 项，以下返回聚合结果与前 {k} 条样本。

- 写入类请求（执行前）：
- 我将修改 {n} 个元素（类别：{categories}），条件为 {filters}。
- 请确认是否继续。

- 写入类请求（执行后）：
- 已完成：成功 {ok}，失败 {fail}。
- 失败主要原因：{reasons}。
- 若当前缺少专用工具：在回复末尾追加“建议新增工具”条目，避免未来重复走动态代码。

## 12. 禁止事项
- 禁止在未确认范围时执行大批量删除/覆盖。
- 禁止在版本不兼容时伪装成功。
- 禁止把“连接问题”错误描述成“业务逻辑完成”。

## 13. 落地建议（当前仓库）
- 在 command 执行前统一插入上下文校验（版本/文档/视图）。
- 在写操作 command 中增加 dry-run 模式（先返回将影响的元素ID）。
- 在 server 侧增加结果摘要器，避免大 payload 返回。
- 在日志中区分“命令实例创建成功/失败”，避免误导排障。

## 14. 单位默认值
- 若用户未指定单位，默认使用公制毫米（mm）。
- 涉及面积/体积时默认分别使用 `m2`、`m3`；如与项目设置不一致，需显式提示换算方式。

## 15. Send Code Tool 校验闭环（工具层强制）
- `send_code_to_revit` 必须先走工具层校验器，再决定是否执行。
- 校验配置文件：`server/src/config/code-execution-rules.json`。
- 校验器实现：`server/src/utils/codeExecutionValidator.ts`。

- 输入参数约定：
- `revit_version`：可选，2019-2026，用于版本兼容规则匹配。
- `validation_mode`：可选，`strict|lenient`（当前默认 strict）。

- 返回约定（校验失败）：
- 返回 `can_retry: true`。
- 返回 `phase: "validation"`。
- 返回结构化 `validation` 对象（包含 `errors[]` 与 `warnings[]`）。
- 每条 issue 至少包含：`ruleId`、`message`、`suggestion`、`line/column`（若可定位）。

- LLM 重试策略：
- Claude 根据结构化 issue 修正代码后重新提交。
- 未通过校验前，禁止执行动态代码。
- 通过校验后，执行结果仍需返回 `warnings`（如有）供用户审阅。
